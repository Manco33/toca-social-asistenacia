# Auditoría de Filtrado por Usuario en Dashboards de Administrador

## 🔍 PROBLEMAS ENCONTRADOS

### 1. **FUNCIONES SIN FILTRO EN actions.ts**

#### ❌ `getEmployees()` - Línea 203
```typescript
export async function getEmployees() {
  const { data: rows, error } = await supabase
    .from('empleados')
    .select('*')
    .order('id', { ascending: true })
    .limit(5000);  // ⚠️ RETORNA TODOS LOS EMPLEADOS
```
**Problema**: Sin autenticación, comparte datos de TODOS los empleados.

#### ❌ `getTodaysEntries()` - Línea 233
```typescript
export async function getTodaysEntries() {

    .from('horarios_gps')
    .select('*')
```

**Problema**: Sin filtro de usuario, muestra registros de todos los técnicos.

#### ⚠️ `getRegistroHoras()` - Línea 596

- Un admin podría consultar horas de cualquier empleado

### 3. **NO HAY CONCEPTO DE PROYECTO DEL ADMIN**

- No existe relación `admin_id` o `proyecto_id` en tabla de empleados
- Los admins no tienen una asociación clara a qué datos pueden ver
- Estructuralmente, la tabla `empleados` NO sabe a qué "departamento" o "proyecto" pertenece

## ✅ SOLUCIÓN PROPUESTA

### PASO 1: Actualizar tabla de empleados
```sql
ALTER TABLE empleados ADD COLUMN admin_responsable_id BIGINT REFERENCES empleados(id);
CREATE INDEX idx_admin_responsable ON empleados(admin_responsable_id);
```

### PASO 2: Crear políticas RLS
```sql
-- Empleados solo pueden ver su propio registro
ALTER TABLE empleados ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can view their own employee record" ON empleados
  FOR SELECT
  USING (id::text = auth.uid());

-- Admins pueden ver empleados bajo su supervisión
CREATE POLICY "Admins can view their employees" ON empleados
  FOR SELECT
  USING (admin_responsable_id = (
    SELECT id FROM empleados WHERE supabase_id = auth.uid()
  ) OR id = (SELECT id FROM empleados WHERE supabase_id = auth.uid()));
```

### PASO 3: Actualizar funciones actions.ts

```typescript
// ANTES
export async function getEmployees(): Promise<any[]> {
  const { data: rows, error } = await supabase
    .from('empleados')
    .select('*')
    .limit(5000);
}

// DESPUÉS
export async function getEmployees(adminId?: string): Promise<any[]> {
  let query = supabase.from('empleados').select('*');
  
  if (adminId) {
    query = query.eq('admin_responsable_id', adminId);
  }
  
  const { data: rows, error } = await query
    .order('id', { ascending: true })
    .limit(5000);
    
  return rows || [];
}
```

## 🚨 RIESGOS DE SEGURIDAD SI NO SE IMPLEMENTA

- **Brechas de privacidad**: Un admin ve datos de todos los empleados de toda la empresa
- **Fraude**: Técnicos podrían ver registros de horas de competidores
- **GDPR/RGPD**: Incumplimiento de protección de datos personales
- **Auditoría**: No hay trazabilidad de quién accede a qué datos
